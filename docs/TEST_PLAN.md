# План тестирования 2.0

## Автоматические проверки

- `node --test test/*.test.mjs`;
- текущий прогон: 28 тестовых файлов, 145 тестов;
- `node --check` для `background.js` и новых core-модулей;
- `git diff --check`;
- `unzip -t` собранного XPI.

## Обязательный ручной smoke

1. Обновить расширение с `1.0.162` или предыдущего test build.
2. Проверить сохранность правил, выбранных ящиков и настроек.
3. Открыть правила, статистику и результаты обработки.
4. Перезапустить почтовый клиент.
5. Проверить отсутствие ошибок фонового процесса.
6. Проверить сохранение, восстановление значений по умолчанию и переход из настроек к правилам.

## Правила и входящие письма

- письмо подходит одному правилу;
- письмо подходит нескольким правилам;
- письмо не подходит ни одному правилу;
- правило ограничено аккаунтом и папкой;
- правило не имеет ограничения папки;
- исключение отправителя действует на все ветки правила с `OR`;
- старый журнал без `headerMessageId` восстанавливает RFC `Message-ID` через доступное письмо, не выводя внутренний ID Thunderbird;
- экспорт большого исторического журнала ограничивает восстановление `Message-ID` восемью параллельными запросами;
- письмо приходит при запущенной программе;
- письмо приходит во время остановки и обнаруживается после запуска.

## Ручное сохранение

- одно вложение;
- несколько вложений одного письма;
- одно вложение подходит нескольким правилам;
- повторное нажатие по уже сохранённому письму;
- одинаковые байты под разными именами;
- одинаковое имя с разными байтами;
- одинаковые вложения в разных письмах;
- частичная ошибка одного из вложений.

## Файлы и восстановление

- удалить сохранённый файл через ОС;
- дождаться автообновления статистики;
- убедиться, что KPI уменьшается, строка исчезает из сохранённых, действие возвращается;
- повторно сохранить файл;
- очистить историю загрузок Thunderbird отдельно и зафиксировать ограничение API.

## Статистика и UI

- KPI считают только письма, попавшие под правила;
- сохранённые содержат только реальные файлы;
- фильтры и группировки дают согласованный результат;
- письмо с несколькими правилами находится при выборе любого совпавшего правила;
- дата «с/по» работает совместно;
- отправитель кликабелен;
- тема и действие открывают исходное письмо;
- вложения одного письма визуально объединены;
- несколько правил и вложений разделены визуально;
- XLSX соответствует экрану.
- обе таблицы центрированы, автоширина и горизонтальная прокрутка сохраняются;
- чекбокс автообновления выровнен с подписью;
- изменение источника статистики во время идущей загрузки не теряется — следующее автообновление подхватывает данные.

## Диагностика и теги

- системные теги почтового клиента сопоставлены с «Рабочее», «Важное», «К исполнению»;
- снимок содержит окружение, счётчики, теги и состояние таблиц;
- пути, email, аккаунты, вложения и правила обезличены;
- исторические события `scan` не включаются;
- ошибка фоновой проверки содержит этап и `messageId`.
- событие ошибки почтового API содержит `mailOperation`.
- отказ `messages.listAttachments` создаёт аудит «Ошибка», метку ошибки и не останавливает полный обход.

## Полный обход и недоступные письма

- кнопка «Остановить проверку» видна только во время активного обхода;
- отключённый «Журнал проверки» не отображается ни до, ни после асинхронной загрузки настроек popup;
- недоступный ящик или неотвечающий API-вызов завершается максимум через 45 секунд, затем обход продолжается;
- письмо, для которого Thunderbird возвращает ошибку `messages.listAttachments`, учитывается в `failedMessages`, имеет запись аудита и не блокирует следующие письма.

## Сброс

- сброс очищает статистику и аудит, снимает метки;
- SHA-реестр освобождается точечно — только для файлов, чьё удаление подтверждено, а не целиком;
- правила и выбранные ящики сохраняются;
- скачанные плагином файлы удаляются только после подтверждения;
- первое сохранение после сброса не выдаёт внутреннее предупреждение о дубле;
- при неподтверждённом удалении одного файла запись SHA-реестра для него сохраняется и ограничение среды фиксируется, а остальные успешно удалённые файлы всё равно доступны для пересохранения;
- при старте плагина реестр дублей сверяется с историей загрузок Thunderbird и освобождает записи по файлам, отсутствующим в истории.

## Критерий решения

- `APPROVED`: все критические сценарии PASS;
- `APPROVED WITH LIMITATIONS`: ограничение Thunderbird API описано и принято;
- `REJECTED`: потеря файла, неверная дедупликация, автоматическое сохранение или недостоверный KPI.
