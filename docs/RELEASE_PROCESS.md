# Процесс выпуска

## Переход на 2.0

1. Взять код 1.0.230/test62 из линии `develop`, обновить номер версии и документацию в отдельной ветке.
2. Проверить тесты и синтаксис, сверить runtime-файлы с релизным commit и собрать XPI по [инструкции](BUILD_PROCESS.md).
3. Merge релизной ветки в `main` запускает `.github/workflows/release-2.0.yml`: workflow повторно проверяет исходники, собирает XPI из merge commit, формирует `SHA256SUMS` и создаёт GitHub Release `v2.0`.
4. Пока ручной [протокол P-001–P-057](PRODUCTION_TEST_PROTOCOL.md) не заполнен, GitHub Release публикуется как **pre-release**. Это даёт доступную версию 2.0 без недоказанного production-статуса.
5. После приёмки исправить критические проблемы в отдельной версии либо явно принять ограничения. Только тогда присвоить статус production baseline; предыдущую reference 1.0.162 оставить для отката.

## Содержание релиза

- имя и версия XPI, commit и SHA-256;
- краткий список новых возможностей и важных исправлений от 1.0.162 до 2.0;
- явное указание, что переход 1.0.230 → 2.0 не меняет функциональный код;
- требования к среде, инструкция обновления, известное ограничение `messages.listAttachments`;
- результаты автоматических проверок и фактический статус ручного протокола;
- ссылки на [README](../README.md), [руководство](USER_GUIDE.md), [историю](RELEASE_HISTORY.md), [CHANGELOG](../CHANGELOG.md) и [GitBook](https://newmishka.gitbook.io/inbox-weaver-dokumentaciya/).

Не помечайте незаполненные сценарии PASS и не выдавайте предварительный релиз за подтверждённый production.
