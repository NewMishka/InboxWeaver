# InboxWeaver — Менеджер писем 2.0

Расширение для почтового клиента с WebExtension API: проверяет письма по правилам, показывает найденные вложения, сохраняет их по явному действию пользователя и формирует статистику и XLSX-отчёт.

> **Основа 2.0:** тестовая версия 1.0.230 / test62. Переход на 2.0 меняет номер версии и документацию, без изменений обработки писем или миграции данных. Ручной протокол P-001–P-057 в целевой среде пока не подтверждён, поэтому 2.0 публикуется как **pre-release**.

**Публичная документация:** https://newmishka.gitbook.io/inbox-weaver-dokumentaciya/

## Быстрый старт

1. Скачайте [XPI 2.0](https://github.com/NewMishka/inbox-weaver/releases/download/v2.0/inbox-weaver-v2.0.xpi) и сверьте [SHA256SUMS](https://github.com/NewMishka/inbox-weaver/releases/download/v2.0/SHA256SUMS). Установите XPI через управление дополнениями почтового клиента («Установить дополнение из файла»). Перед обновлением сохраните файл правил в JSON через страницу «Правила».
2. Откройте значок расширения → **Правила**. Выберите ящик и папки, задайте название и условие, укажите папку результата, нажмите **Создать правило**.
3. Нажмите **Проверить письма по правилам** для обхода существующей почты. Для новых писем включите в **Настройках** «Автоматически проверять новые письма».
4. Откройте **Статистику**. Подходящие письма видны в результатах; нажмите **Сохранить вложения** у письма или **Сохранить все вложения** для массового ручного сохранения. Проверка писем сама файлы не сохраняет.
5. В **Статистике** нажмите **Экспорт XLSX** или **Отчёт руководителя XLSX**. Автоматическую выгрузку полного отчёта можно включить в настройках.

Подробные шаги, примеры запросов и объяснение сброса: [Руководство пользователя](docs/USER_GUIDE.md).

## Возможности

| Раздел | Что делает |
|---|---|
| Правила | Условия по теме, тексту, отправителю и расширению вложения; несколько ящиков и папок, AND/OR/исключения, импорт и экспорт JSON. |
| Проверка | Live-обработка новых писем, догоняющая проверка при запуске, ручной полный обход с прогрессом и остановкой. |
| Вложения | Ручное сохранение, варианты организации папок, глобальная проверка дублей по SHA-256, проверка доступности файлов. |
| Статистика | KPI, фильтры, две группировки, сортировка, независимая пагинация писем и сохранённых вложений. |
| Отчёты | Ручной XLSX, отчёт руководителя и автоматический полный XLSX по расписанию. |
| Диагностика | Журнал проверки, служебные метки, снимок состояния и структурированный журнал разработчика. |

Основная испытательная среда проекта — РЕД ОС 7.3 и почтовый клиент с нужными WebExtension API. Не все реализации API одинаково обрабатывают отдельные письма: известное ограничение `messages.listAttachments` и статус ручной проверки перечислены в [заметках 2.0](docs/RELEASE_2.0.md).

## Как проект дошёл до 2.0

| Этап | Содержание |
|---|---|
| 1.0.146 и 2.2.5l | Архивные линии; их номера не означают, что 2.0 наследует код 2.2.5l. |
| 1.0.162 | Последняя зафиксированная production reference для сравнительной проверки. |
| 1.0.163–1.0.176 | Стабилизация обхода и интерфейса, правила, фильтры, SHA-256; явное ручное сохранение. |
| 1.0.177–1.0.196 | Исправления дублей, доступности и сброса; Live/catch-up; вынос сервисов. |
| 1.0.197–1.0.211 | Модульные тесты, аудит, диагностика, теги, оптимизация и пакетная запись журналов. |
| 1.0.212–1.0.220 | Пагинация, автоотчёты, UX сохранения, модель XLSX, RFC Message-ID и массовое сохранение. |
| 1.0.221–1.0.230 | Файл правил, управляемая остановка, тайм-ауты, устойчивость обхода, исключение в сложном правиле и восстановление RFC Message-ID. |
| 2.0 | Релизная упаковка проверенного исходного кандидата и единая документация; ручная приёмка отмечается отдельно. |

Каждая зафиксированная версия, включая исправления и тесты: [полный CHANGELOG](CHANGELOG.md). Связь этапов, артефактов и ограничений: [история и дорожная карта](docs/RELEASE_HISTORY.md).

## Проверка исходников

```bash
node --test test/*.test.mjs
node --check background.js
find core modules mainPopup rulesTab settingsTab statisticsTab auditTab -type f \( -name '*.js' -o -name '*.mjs' \) -print0 | xargs -0 -n1 node --check
```

Сборка выполняется из зафиксированного commit по [инструкции](docs/BUILD_PROCESS.md). Для 2.0 XPI и `SHA256SUMS` прикладываются к GitHub Release `v2.0`; бинарные файлы не хранятся в основной исходной ветке.

## Статус и дальнейшая работа

Критерии перехода к эксплуатационной базе: заполненный ручной протокол, решение по обнаруженным ошибкам, контроль обновления профиля и отката. Следующие направления — версия схемы хранения и миграции, страничные журналы, производительность больших ящиков и дальнейшая модульность. [План работ](ROADMAP.md).
